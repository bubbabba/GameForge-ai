## Pattern
- Backend: `POST /games/:id/chat` — auth-gated, verifies game ownership, calls Claude with full game code as context, returns `{ updatedCode }`. System prompt tells Claude to output ONLY raw HTML, no prose, no fences.
- Frontend: `GameEditor.tsx` — 4 panels: left sidebar (file explorer + settings), center-top (iframe preview), center-bottom (AI chat), right (code textarea).
- Hook: `useChatEditGame` from `@workspace/api-client-react` (generated by orval).

## Decisions
- **Textarea locked during AI edit** (`readOnly={isThinking}`): prevents race condition where user edits code mid-flight and AI response overwrites them.
- **Undo stack** (`undoStack.current: string[]`, max 20): snapshot pushed before each AI edit, popped on undo. Undo is surfaced both via header button and inline "Undo this change" link on assistant messages.
- **Publish-before-save fix**: `handlePublish` saves first via `updateGame.mutate` and only calls `publishGame.mutate` in `onSuccess` — prevents publishing stale code.
- **Auto-save after AI edit**: `doSave(updated, titleRef.current)` called immediately after each successful chat response.

**Why:** Correctness and UX — the chat loop must be atomic (lock → AI edit → apply → unlock) to avoid silent data loss.

## Limits
- `MAX_CHAT_MESSAGE_CHARS = 2000` (message input)
- `MAX_CHAT_CODE_CHARS = 80000` (code context sent to Claude, truncated not rejected)
- Claude model: `claude-sonnet-4-5`, `max_tokens: 16000`
